# 潛光遠征 功能清單與上鏈評估 v3（草案）

狀態：草案（2026-10-08），給老闆勾選。流程照老闆定的三步：

1. **功能定案**：這份第 1～2 章，老闆勾選、刪改。
2. **上鏈評估**：第 3～4 章，每個功能能不能接上智能合約、怎麼接、風險是什麼。
3. **精緻化與動態化**：第 5 章，用哪些開源工具把畫面和玩法做得更像一款大作。

標記：
- **【已做】** 已在預覽版（/game/lightdive/preview）可以玩。
- **【建議】** 我以遊戲設計師的角度建議加入，等老闆決定。
- **鏈上**：規則、資產或金流由合約執行。
- **鏈下**：網站或伺服器處理，不影響資產。
- **混合**：結果在鏈上，畫面或計算在鏈下。

## 4. 上鏈的重點設計與風險

### 4.1 一次出發在鏈上怎麼跑
1. `dive(隊伍, 目的地)`：合約檢查出發令、隊伍次數、門檻；用鏈上資料算出同頻、超出門檻、今天的星象；記下這次的勝算表編號。用同一筆的資料決定**有沒有事件卡、是哪一張**，馬上就能顯示。
2. `choose(出發編號, 選項)`（只有出現事件卡時）：必須在**該小時的隨機種子公開之前**送出；種子公開後合約拒絕，確保沒有人能先看到結果再選。
3. 種子公開後，畫面就能顯示結果、倍率、耗損（揭曉）。
4. `settle(...)`（當天結束後，任何人都能呼叫，網頁會自動代勞）：耗損航程、航程歸 0 的進入停泊、扣出發成本（95% 回池、5% 銷毀）、依當天比例分配 RVYN。

和預覽版的差別：預覽版揭曉時立刻入帳；正式版揭曉時先顯示「帶回的光塵」和預估 RVYN，**實際 RVYN 要等當天結束才確定**（因為要看全體的光塵總和）。

### 4.2 每天的光和星象要「鏈上可驗證」
- 正式版改成用 `keccak256(日期, 目的地)` 算出每個目的地今天的光和星象，合約和網頁用同一個公式，任何人都能驗算。
- 預覽版目前用的是另一個隨機函式，接合約時會換成這個公式（畫面不用改）。

### 4.3 抽卡價自動換算
- Robinhood Chain 已經有 Uniswap v3（2026-07 主網上線就部署了），v3 的池子內建時間平均價格（用時間戳記，不受 Arbitrum 區塊號碼的特殊行為影響）。
- 做法：建立 RVYN／WETH 的 v3 池；Minter 每天讀一次 24 小時平均價格，依開賣當天記下的 ETH 價值換算，限制在 10%～200%、每天最多 ±10%；流動性低於門檻時不更新。
- 風險：池子太小時價格容易被拉。最低價、最高價和每天 ±10% 是主要防線；另外要求池子的觀測點數量足夠。

### 4.4 手續費與簽名次數
- 一般玩家一天大約要簽：出發 3 次、抉擇 0～3 次、提領偶爾 1 次。結算由網頁批次代勞。
- 建議做功能 28「一次出發多隊」，3 次出發可以合成 1 筆。
- Robinhood Chain 是 L2，手續費很低；之後也可以評估用工作階段金鑰（session key）減少彈窗，但要另外做安全評估，先不做。

### 4.5 主要風險
| 風險 | 對策 |
|---|---|
| 合約變複雜，審計費用和時間增加 | 數值全部放在 Config，Expedition 只寫流程；先在測試網跑完整一季再審計 |
| 18 張勝算表、16 張事件卡的選項存在鏈上 | 每張表最多 6 列，寫入時檢查機率總和和平均倍率；選項只存效果代碼 |
| 抉擇的時間窗（揭曉前） | 合約以「該小時種子是否已公開」判斷；畫面倒數提醒 |
| 隨機數由營運方提供 | 先承諾後公開，48 小時沒公開就以 1.0 倍結算；之後可換 VRF |
| 市集合約管理玩家資產 | 獨立合約、獨立審計；先上測試網跑一段時間 |

## 5. 精緻化與動態化：工具建議（第三步）

| 工具 | 授權 | 用在哪裡 | 建議 |
|---|---|---|---|
| PixiJS 8（已在用） | MIT | 星圖、光橋、揭曉的 WebGL 畫面 | 星圖改用 Pixi 繪製，加景深和視差 |
| pixi-filters（已安裝） | MIT | 光暈、上帝光、扭曲、色散 | 星團的光暈、核心的光芒、傳說揭曉的畫面扭曲 |
| RevoltFX | MIT，支援 Pixi 8 | 粒子特效（光塵、爆發、拖尾），有線上編輯器 | 光橋拖尾、揭曉爆發、抽卡翻牌的光 |
| GSAP（已安裝） | 免費使用 | 時間軸動畫 | 揭曉的分鏡、鏡頭推進、數字跳動 |
| Rive | 執行端開源 | 角色動畫（狀態機） | 讓 Rovyn 會眨眼、說話、對結果有反應；美術要用 Rive 編輯器製作，配合你最後提供的美術 |
| Howler.js | MIT | 音效播放 | 統一管理音效和背景音樂 |
| Kenney 音效包 | CC0（公眾領域） | 介面音效、科幻音效 | 按鈕、出發、揭曉、抽卡的音效 |
| Godot | MIT | **不做成網頁遊戲本體**；用來離線製作特效序列圖（例如用 Particles Renderer 外掛把粒子特效輸出成連續圖） | 做出幾個招牌特效，輸出成圖片給 Pixi 播放 |

我的判斷：遊戲本體繼續用網頁技術（錢包、合約、手機都已經接好）；Godot、Rive、RevoltFX 當成「美術和特效的生產工具」。這樣畫面可以接近大作，又不用重寫遊戲。

**第三步的施工順序（建議）**
1. 星圖改成 Pixi 場景：深空視差、星團光暈、可拖曳和縮放、點星團時鏡頭推進。
2. 揭曉分鏡：光橋回收、粒子爆發、倍率跳動、依結果不同的特效等級（一般／豐收／大豐收／傳說）。
3. 音效系統：Howler.js 加 Kenney 音效，可以靜音。
4. 抽卡翻牌：卡背、翻轉、稀有度光柱。
5. Rovyn 動態化：先用現有圖片做呼吸、說話的動態；美術完成後換成 Rive 角色。
6. 介面細節：數字動畫、按鈕回饋、頁面轉場。
