## Defect found after the first publish, fixed in this release

The badge returned 500 on every request after the first one: a response served from the edge cache has immutable headers and the framework adds its own after the handler returns (`Can't modify immutable headers`). Found because the asset-page preview image would not render; confirmed with `wrangler tail`. The route now returns a mutable copy of a cache hit, and the route test's cache mock was changed to return immutable headers as the real cache does, so the case is covered.

## Known caveats

- The health panel reads the sale through the V5 getter names. It must be updated when a V6 sale exists.
- The badge shows the creator-chosen token name and symbol (escaped). The patch documentation asks the founder to decide a naming policy for abusive names.
- `packages/contracts/v6/RovynPresaleV6.sol` is in the source inventory (one of the 15 changed files) but is an uncompiled draft, not imported by the site, not deployed, and not audited.
