# Production release 2026-10-05-26

Recorded 2026-10-07 (UTC+8). Worker 07ece9c8-189d-4995-bbc7-151300a2c20d. Released by Claude Code under the founder's direct-production authorization for website updates.

The founder asked for the site's X fetching to be removed completely.

## What was removed

- **Public endpoint:** `GET /api/x-updates`. It now returns 404.
- **Admin actions:** `x-update-import` and `x-update-remove`. Both were removed from the challenge allow-list and from the admin handler.
- **Scheduled sync:** the Worker `scheduled` handler (cron sync and heartbeat). Crons were already empty.
- **Config var:** `X_AUTO_SYNC`, removed from `wrangler.production.jsonc` and the `lib/server.ts` bindings type. Deploys use `--keep-vars`, so the old value may linger on the Worker. Nothing reads it.
- **Code:**
  - `lib/x-updates.ts`, which made the only outbound request to `publish.x.com/oembed`.
  - `lib/x-updates-store.ts`, `lib/x-updates-storage.ts`, `lib/x-feed-view.ts`, `lib/x-auto-sync.ts`
  - `components/x-profile-feed.tsx`
  - `app/x-updates.css`, plus its import in `app/admin/legacy.css` and the X card rules in `app/rv.css`
- **Tests:** `tests/x-updates.test.ts`, `tests/x-feed-view.test.ts`, `tests/x-auto-sync.test.ts` and `tests/x-auto-integration.mjs`.
  - The three X checks in `tests/api-integration.mjs` were replaced by one check: the endpoint is 404, both admin actions are rejected, and `/latest-info` shows the development log with no X post.

## What was kept and not changed

- Links to the official X account in the header, footer, terms and pages remain.
- The D1 `settings` rows `official:x-updates`, `official:x-sync-state`, `official:x-sync-lease` and `official:x-cron-heartbeat` are left in place. Nothing reads them now, and deleting them would be a production database write.
- No D1 migrations, no contract change and no onchain transactions.
